# agent_select — 단어 선택 개선 (W1, W3)

## 1. 조사 결과

환경: node v24.19 (ICU 78.3), 데스크톱 Firefox 160(헤드리스, Marionette로 `Intl.Segmenter` 직접 실행), Google 번역 엔드포인트 실호출.
Firefox Android 실기기는 확인하지 못했다(같은 Gecko라 데스크톱과 같을 것으로 추정 — 미검증).

### 원인 A — Firefox에서 `isWordLike`가 틀려 단어가 아예 탭되지 않는다 (확정, 가장 큼)

Firefox(ICU4X)는 사전에 있는 단어 일부를 `isWordLike:false`로 돌려준다. 기존 코드는 `isWordLike`인 세그먼트만 `.sao-word`로 감싸므로 이 단어들은 span이 없어 탭해도 반응이 없다. node(ICU4C)에서는 재현되지 않는다. 괄호가 `isWordLike:false`:

| 입력 | Firefox 160 | node 24 |
|---|---|---|
| 東京スカイツリーに行きたいです | (東京)·スカイツリー·に·行き·たい·です | 東京·スカイ·ツリー·に·行き·たい·です |
| 大丈夫ですか？ | 大丈夫·(です)·か·(？) | 大丈夫·です·か·(？) |
| 似ている人を見た | 似·てい·る·人·を·(見)·た | 似·て·いる·人·を·見·た |
| 食べられなかった | 食·べら·れな·(か)·(った) | 食·べら·れ·なか·っ·た |
| 早く寝たほうがいいよ | 早く·寝·た·ほうが·(いい)·よ | 早く·寝·た·ほうが·いい·よ |
| 你喜欢看电影吗？ | 你·喜欢·看·电影·(吗)·(？) | 你·喜欢·看·电影·吗·(？) |

### 원인 B — 일본어 활용형이 1~2글자 조각으로 잘린다 (확정)

두 엔진 모두 동사·형용사 활용형을 형태소보다 잘게 자르고, 엔진마다 자르는 위치도 다르다.

| 입력 | Firefox 160 | node 24 |
|---|---|---|
| 昨日は寿司を食べました | 昨日·は·寿司·を·食·べ·まし·た | 昨日·は·寿司·を·食·べ·ま·した |
| 行ってきます | 行·って·き·ます | 같음 |
| 日本語を勉強しています | 日本語·を·勉強·し·てい·ます | 같음 |
| 学校に行かないでください | 学校·に·行·かな·い·でく·だ·さい | 学校·に·行·か·ない·で·くだ·さい |
| この映画はとても面白かったです | この·映画·はと·て·も·面白·か·ったで·す | この·映画·は·とても·面白·か·っ·た·です |
| 走っている人がいます | 走·って·いる·人·がい·ます | 같음 |

조각을 그대로 조회하면 뜻이 틀리다(원인 D 참고): `食`→"먹다"(읽기 Shoku), `べ`→"베", `まし`→"마시", `行`→"행"(Gyō), `って`→"라고".

다른 언어:
- 중국어(간/번체): 대체로 단어 단위. 가끔 구를 한 덩이로 묶는다(`我想去`, `不太好`, `吃了`) → 줄일 수 있어야 한다.
- 태국어: 단어 단위로 잘 나뉜다(Firefox는 `มาก`→`มา·ก`처럼 가끔 쪼갬).
- 한국어: 어절 단위(`초밥을`, `먹었습니다`). 번역은 어절째로도 맞게 나온다(`초밥을`→Sushi). 조사 분리는 하지 않는다.
- 영어: `don't`, `it's` 유지. 하이픈은 분리(`well·-·known`), 구동사(`pick up`)는 두 단어 → 넓힐 수 있어야 한다. `p.m.` → `p.m` + `.`

### 원인 C — 탭 대상이 작고, 빗나가면 플레이어가 반응한다 (계산으로 확인)

- 글자 크기 `clamp(14px, 4.2vw, 26px)`: 폭 390px에서 16.4px, 가로 844px에서 26px. 줄 높이 1.35 → 줄 상자 22px(390px).
- `.sao-word`는 inline span이라 탭 영역이 글자 상자뿐: 한자 한 글자 = 약 16×20px(390px). 권장 44px의 1/3.
- 줄(`.sao-line`)은 `pointer-events:none`이라 단어 사이 공백·문장부호·줄 위아래 1px 패딩을 누르면 탭이 플레이어로 떨어져 재생 토글/컨트롤 표시가 일어난다. 원인 A의 "span 없는 단어"를 눌러도 같은 일이 생긴다.

### 원인 D — 사전 응답 (실호출로 확인)

- `dt=bd`(품사별 사전 항목)는 한쪽이 영어인 쌍에서만 온다. `ja→ko`, `zh-CN→ko`, `th→ko`, `fr→ko`, `ko→en`은 모두 `[1] = null`. `ja→en 食べる`, `zh-CN→en 学习`, `en→ko run`은 항목이 있다. 활용형(`ja→en 食べました`)은 영어 쌍이어도 null.
- 번역(`dt=t`)은 항상 온다. 기존 코드도 항목이 없으면 번역만 보여 준다(문제 없음). 다만 조각을 조회하면 번역 자체가 틀리다(원인 B).
- `dt=rm`을 추가하면 `data[0]`의 마지막 원소가 `[null, null, <번역의 로마자>, <원문의 읽는 법>]`으로 온다. 예: `食べました`→`Tabemashita`, `学习`→`Xuéxí`, `먹었습니다`→`meog-eossseubnida`, `กิน`→`Kin`, `run`→`rən`. 영어→X에서 원문 읽기가 없으면 원소 길이가 3이다.
- `dt=md/ss/ex/at`는 `ja→ko`에서 추가 정보가 없었다(대체 번역 `at`만 옴). 쓰지 않는다.

### 그 밖에 확인한 것

- 전각 공백·`[音楽]`·줄바꿈(parseJson3가 공백으로 합침)은 비단어 세그먼트로 잘 분리된다. 문제 없음.
- 큐가 바뀌는 순간(터치 시작~끝 사이)에 줄이 다시 그려지면 탭한 span이 사라져 click이 원래 단어에 닿지 않을 수 있다. 드물고 싸게 고칠 방법이 없어 그대로 둔다(미해결).

## 2. 접근 방식

1. **단어 판정**: `isWordLike` 대신 "글자/숫자가 하나라도 있으면 단어"(`/[\p{L}\p{N}]/u`). 엔진과 무관하게 같은 결과. (원인 A)
2. **일본어 후처리 `mergeJa`**(일본어일 때만, 순수 함수): 
   - 단어 첫 글자가 될 수 없는 가나(っゃゅょんー)로 시작하는 조각은 앞 단어에 붙인다.
   - 한자가 든 어간 뒤의 히라가나 조각(활용 어미·조동사)을 어간에 붙인다. 조사·계사·흔한 부사(정지어 목록)를 만나면 멈춘다. `か/が/しか/から/かな`는 뒤 조각을 보고 어미인지 판단(`分か·り`, `行か·ない`, `曲が·って`, `嬉しか·った`).
   - 한자 2자 이상 명사는 する 활용(し/す/さ…)일 때만 붙인다(`勉強しています`). 4자 이상 히라가나 조각은 붙이지 않는다(`ちょっと`).
   - 말뭉치 68문장을 두 엔진에서 돌려 확인: 대부분 `食べました`, `行ってきます`, `知らなかったん`, `面白かった` 같은 단위가 된다. 한계(틀리는 예): `人がいます`(엔진이 `がい`로 자름), `誰かいます`, 한자 없는 동사(`かかり|ます`, `ござい…`), 엔진이 조사와 붙여 자른 조각(`でく`, `はと`). 틀린 경우는 범위 조절로 바로잡는다.
   - 대안: 형태소 분석기(kuromoji, 사전 수십 MB)·TinySegmenter(외부 코드 반입) → 의존성 금지라 제외. 후처리 없이 범위 조절만 → 거의 모든 동사에서 3~4번 눌러야 해서 제외.
3. **선택 범위 조절 UI**: 팝업에 `시작 ◀ ▶ / 끝 ◀ ▶` 버튼. 탭 시점에 문맥 문장을 단위 배열로 복사해 두므로 자막 줄이 바뀌어도 동작한다. 단위는 세그먼트, 단 한자·가나 단어는 글자 단위(중국어 `我想去`→`想`, 일본어 오병합 교정 가능). 공백·문장부호는 건너뛴다. 범위가 바뀌면 그 텍스트로 재조회하고, 단어장에도 그 텍스트가 저장된다. 팝업에 문맥 문장을 선택 부분 강조와 함께 보여 준다. 순수 로직(`selectionUnits`, `moveEdge`)은 `pick-tracks.js`에 두고 node로 테스트.
4. **탭 대상**: 학습 언어 줄의 줄 높이 1.35→1.6, 패딩 1px→6px, 줄 자체를 `pointer-events:auto`로 하고 줄 안의 빈 곳을 누르면 가장 가까운 단어로 처리(플레이어로 새지 않음). 390px에서 탭 가능한 높이 약 20px→38px. 글자 폭은 글자 크기에 묶여 있어 그대로(자막 배율 설정으로 키울 수 있음).
5. **사전 응답**: 요청에 `dt=rm` 추가, `LookupResult.reading`(원문과 같으면 생략). 팝업 단어 옆에 작게 표시.
6. **오버레이 밖 단어**: `closest('[data-sao-context]')` 등으로 문맥·번역·시각을 읽는다. 범위 조절은 문맥 문장을 다시 분절해 단어 위치를 찾고, 못 찾으면 버튼을 숨긴다.

## 6. 변경 사항 (계획과 달라진 점)

- **넓힐 때는 세그먼트 단위, 줄일 때만 글자 단위.** 처음에는 한자·가나를 양방향 모두 글자 단위로 옮겼는데, 하네스에서 `寿司を` → `寿司を食` → … 처럼 한 글자씩만 늘어 불편했다. 넓히기는 다음 세그먼트 끝까지(`寿司を` → `寿司を食べました`), 줄이기는 한 글자씩으로 바꿨다. 단위에 세그먼트 번호(`seg`)를 붙였다.
- **가로 화면은 2열 격자.** 컨트롤을 한 열로 쌓으면 844×390에서 팝업이 자막 줄까지 내려온다. 가로에서는 왼쪽에 단어·문맥·범위 버튼, 오른쪽에 뜻·추가 버튼을 두어 높이를 줄였다(폭 최대 720px).
- `から` + `ない`(分からない)도 어미로 본다. `かな`는 뒤가 い/か일 때만(行かな·い, 書かな·か·った).

## 7. 검증 결과

- `npm test`: 21개 통과. `npm run lint`: 오류 0, 경고 2(기존 manifest 경고).
- 최종 `segmentWords`를 Firefox 160(헤드리스)에서 말뭉치 68문장에 실행: `食べました`, `行ってきます`, `勉強しています`, `食べられなかった`, `分からない`, `面白かったです`, 그리고 이전에는 탭할 수 없던 `東京`·`です`·`吗`가 단어로 나오는 것을 확인. 남는 오분절 예: `行かないでく|だ|さい`, `はと|て|も`, `人がいます`, `ありがとう|ご|ざいま|す`.
- 하네스(`browser` 스텁 + 가짜 조회 응답, 워크트리 밖)를 헤드리스 Chrome과 헤드리스 Firefox 160에서 실행:
  - 탭 → 팝업. 범위를 넓히고 줄일 때마다 그 텍스트로 재조회. 자막 줄이 바뀐 뒤에도 범위 조절 동작. 조절한 범위(`寿司を食べました`)가 단어장에 저장. 저장 후 범위를 바꾸면 추가 버튼이 다시 활성.
  - 오버레이 밖 단어: `data-sao-context`, `data-sao-context-translation`, `data-sao-time`(83)이 항목에 들어감. 문맥에 없는 단어는 범위 버튼 없이 열림.
  - 줄의 빈 곳(단어 3px 위) 클릭 → 가장 가까운 단어가 열림.
  - 레이아웃: 세로 390×844(팝업 y 412~832, 자막 y 135~241), 세로 360×640, 가로 844×390(팝업 y 8~187, 자막 y 214~343). 모두 팝업이 화면 안, 자막과 겹치지 않음, 버튼 44px 이상, 가로 스크롤 없음. 스크린샷으로 확인.
  - 탭 영역: 390px에서 학습 언어 줄(한 줄) 높이 38px(이전 약 24px, 그중 탭되는 것은 span 높이 18px뿐). 영어 `I`의 span은 폭 4.6px이라 스냅이 없으면 사실상 탭할 수 없었다.
- 미검증: Firefox Android 실기기, 실제 m.youtube.com 페이지(플레이어의 터치 처리와의 상호작용, 전체화면), 실제 번역 응답을 붙인 종단 동작(하네스는 가짜 응답. 응답 형식은 실호출로 확인하고 파서 테스트로 고정).

## 8. 미해결

- 일본어 후처리는 휴리스틱이라 틀리는 경우가 남는다(위 예). 범위 조절로 교정.
- 글자 폭은 그대로다. 한자 한 글자 단어는 390px에서 폭 약 16px. 스냅과 줄 높이로 보완했고, 더 키우려면 자막 배율 설정을 쓴다.
- 자막 줄의 강조(`sao-dict-active`)는 처음 탭한 span에만 남는다. 조절한 범위는 팝업의 문맥 줄에서 강조된다.
- 학습 언어 줄이 `pointer-events:auto`가 되어, 사전 설정을 꺼도 줄 상자 위의 탭은 플레이어 컨트롤 오버레이로 가지 않는다(단어 span은 원래도 그랬다).
- 큐가 바뀌는 순간의 탭 유실(1절).
- 범위 버튼을 빠르게 누르면 누를 때마다 조회 요청이 나간다(캐시는 있음, 디바운스 없음).
- 읽는 법은 Google의 로마자 표기다(가나 읽기가 아니라 `Tabemashita`).
